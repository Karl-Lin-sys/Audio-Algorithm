# 技術選定と検証設計

**提案は、GTCRNを低演算量の単一マイク候補、公式MVDRを多マイクの数学的基準法、ESPnetを将来の比較実験基盤として評価することです。量産採用の確定ではありません。** 芯片、RAM、入力構成、電力、遅延上限、実録音が未指定なので、性能優劣を実測なしで断定しません。出典IDは[一次資料台帳](sources.md)に対応します。

## 根本原因について言えることと、3つの具体策

求人票は障害ログではありません。実際の故障、汎化失敗、メモリリークの根本原因は**未特定**です。以下は公開一次資料の失敗機序を用いた検証計画で、企業にその欠陥があるとの主張ではありません。

### 1. 分割単位の誤り・テストへの過適合を検査する

同一音源から切り出した録音や増強版が訓練・テスト両方にあれば、独立した未知録音に対する誤差を測れません。評価に繰り返し合わせるモデル選択も楽観的な結果を生みます。分割と選択バイアスの枠組みは[P5](https://pmc.ncbi.nlm.nih.gov/articles/PMC10499856/)に基づきます。

**具体策:** 分割を切り出し・増強より先に固定し、話者、セッション、元音源、雑音元、RIR、同一ファイルhashの跨ぎを`audit_manifest`で拒否。前処理の推定・早期停止・閾値調整はtrain/valだけで行い、最終testを凍結する。事前学習データとの重複は著者の学習来歴を別に調査する。

**判定実験:** 現行分割と依存関係を排した分割を同条件で学習比較し、独立外部集合で再評価する。スコア差だけで原因確定せず、漏洩経路の記録と除去を確認する。本監査の合格は全漏洩排除の証明ではない。

### 2. 合成データ偏重・少数条件の埋没を検査する

RealMANは合成と実収録の隔たりを扱い、URGENTは入力・劣化・評価指標の多様性を重視します。[P3](https://proceedings.neurips.cc/paper_files/paper/2024/hash/bf8f6f5b017dc60d0c4e28a7a9a4ee7b-Abstract-Datasets_and_Benchmarks_Track.html)、[P4](https://www.isca-archive.org/interspeech_2024/zhang24h_interspeech.pdf)

**具体策:** 実録音を、言語、SNR、雑音種、室内外、距離、装着、マイク個体で事前層別化。学習時の不足条件補充と評価時の集計重みを分ける。全体平均・条件macro平均・最悪条件・失敗率を併記する。評価集合を多数条件に都合よく再サンプリングしない。

理論上、録音平均は `sum(n_g/N * mean_g)`、等重み条件平均は `sum(mean_g)/G` で異なる母集団量です。99件が+10 dB、1件が−10 dBなら全体+9.8 dBでも条件平均0 dB、最悪−10 dB。この算術をテストで検証しています。等重み平均も実利用分布の不偏推定を保証しません。存在しない条件の性能は測れません。

**判定実験:** 分布・録音条件を記録した独立実音声を使い、同一録音での差を比較。話者/セッション単位の対応付きbootstrap信頼区間とブラインド聴取を追加する。今回は実データと被験者がないため、信頼区間・聴取結果を作成していません。

### 3. モデル構造・信号経路・製品要求の不整合を検査する

GTCRN公式実装にはstreamabilityに関わるfeature rearrangementの修正説明があります [C1]。FINALLYの音質研究 [P2] は本製品の音声内容保持・遅延要件の保証ではありません。**今回のMVDR**は全発話で共分散を集計するため、未来のフレームを使用します。この構造はコードから確定でき、低遅延製品の実装とは明確に区別します。

**具体策:** 製品版は状態を持つ因果推論、逐次共分散、固定バッファを別設計し、過去入力が同じで未来だけ異なる対を使って出力不変性を検査する。量子化前後で振幅・位相・内容保持を比較し、機種上でp95/p99処理時間、ADC→DAC遅延、RAM、熱平衡電力、ドロップ率を測定する。これは実施予定で、今回の実測と混同しない。

MVDRでは `Rn + lambda I` の対角荷重が数値安定化の手段になりますが、lambdaを大きくすると空間選択性とのトレードオフがあります [D2]。低精度化で逆行列系の安定性が保たれるとは限りません。マスク支持がない周波数は参照マイクへ戻し、非有限結果は明示失敗にします。

**判定実験:** クリップ、無音、マイク欠損、方向移動、double-talkを切り分ける。参照・前処理を固定したアブレーションでどのモジュールが劣化を生むかを測る。AECには再生参照と近端音声、ANCには制御対象の音響経路、補聴には個別の聴覚要求が必要で、単一マイク降噪モデルだけでは置換できない。これらは本実装の対象外。

## 評価指標を使う条件

現在コードで計算するのはゼロ平均SI-SDRと改善量のみです。スケール不変なので出力ゲイン誤りは見逃し得ます。無音・欠落・クリッピング・利得も別に管理します。PESQ、POLQA、NISQA、3GPP適合性は計算・認証していません。名称だけを記載して適合を示しません。

今後の評価仕様案は、信号忠実度、了解度、聴取品質、音声内容保持、遅延、失敗率を別々に合格判定することです [P4]。PESQ等の実装・使用条件を確認したうえで追加し、学習に使った知覚スコアだけを独立評価にしません。VADなど分類問題を追加した場合、クラス別precision/recall、macro F1、PR系指標を検討し、降噪という回帰問題にaccuracyを無理に適用しません。

## 関数別計算量とメモリ

以下は本コードと公式API構造からの導出で、実測時間ではありません。N=波形サンプル数、C=マイク数、L=FFT長、T=フレーム数、F=L/2+1、G=条件数、K=監査軸数、B=ファイルbyte数、P=モデルパラメータ数、A=1フレームのモデル演算、H=1フレームの中間活性サイズ、R=反復数、W=warmup数、Q/S=処理1回の時間/空間。

|関数|時間|追加空間・理由|
|---|---|---|
|read_wav|O(CN)|O(CN)。PCM読み込み・型変換。読込前に長さ上限を確認|
|write_wav|O(N)|O(N)。有限値/利得確認・PCM変換|
|si_sdr|O(N)|O(N)。平均除去、内積、残差。epsilon正則化値で±無限大の厳密値ではない|
|mvdr_spectrum|O(FTC²+FC³)|保守的上界O(FTC²+FC²)。外積PSD推定と周波数ごとの線形求解。公式内部実装で一時テンソル量は変化|
|audit_manifest|平均O(NK)|O(NK)。hash map。極端な衝突を除く平均計算量。文字列長も可変ならその総長を追加|
|summarize|O(N+G)|O(G)。CLIの入力JSON保持分O(N)は別|
|benchmark_cpu|O((R+W)Q+R log R)|O(S+R)。出力を保持せず実行時間だけ保存。ソートでp95|
|sha256_file|O(B)|O(1)。1 MiB固定バッファ|
|load_gtcrn|O(P+B)|O(P)。モデル生成・重み読込。Pythonソースのロード分を追加|
|enhance_gtcrn|O(TL log L+TA)|O(TF+TH+P)。固定モデルなら入力長に線形、全発話活性を保持するオフライン方式|
|synthetic_demo / 内部process|上記STFT・MVDR・ISTFT・benchmarkの合計|固定2秒fixture。一般化するとMVDRと同じ最大一時領域|
|main|選択した関数の時間＋ファイル/JSON読込|選択した関数の空間＋入力JSON。引数解析は引数長に線形|

再帰層単体は入力次元D・隠れ次元Hで概ねO(T(DH+H²))、畳込みは出力位置数×kernel要素×入出力channelに依存します。モデル一般の演算量をパラメータ数だけでO(P)とは表しません。

推論グラフは作らず、モデルは一度ロードし、出力テンソルの履歴を蓄積しません [D3]。ただし「メモリリークがない」という包括証明ではありません。長時間運用のRSS・allocator・ドライバ・リアルタイム音声I/Oのsoak試験は別に必要です。float64はMVDRの数値確認、float32は公式GTCRN入力に使用し、全面的なhalf精度化はしていません。

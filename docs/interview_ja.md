# 面接で説明するための資料

この資料は準備用です。合格は保証できません。コードを読んで動作を確認した範囲、自分で実施した実務、未経験の項目を正確に区別してください。

## 90秒の説明例

「この職務では、音声品質の改善を消費電力、遅延、部品コスト、量産の再現性と同時に成立させることが重要だと理解しています。今回の準備では、公式実装に基づくGTCRN推論と多マイクMVDRの検証コードを用意しました。研究のスコアを直接採用判断には使わず、話者や収録セッションの分割監査と条件別評価を実装しました。

GTCRNの論文値と現在の実装値が異なる点も追跡しています。理想マスクによる合成デモと、実製品の性能を区別しています。実チップと録音条件を確認できれば、品質・最悪条件・p99処理時間・ADCからDACまでの遅延・RAM・電力を計測し、POCから量産までの判定基準をチームと合意します。今回のコードはオフライン研究用で、AEC、ANC、補聴効果や量産実績を示すものではありません。」

自分の経験を追加するときは、製品名の公開可否、担当範囲、チーム規模、出荷段階、測定条件を確認し、実際の数値だけを述べてください。AI支援で準備した試作を、過去に自分が量産した成果として説明しないでください。

## 想定質問と答え方

|質問|説明の軸|
|---|---|
|なぜ最新で最大のモデルを採用しないのか|候補は品質だけでなく制約適合で選ぶ。現在はチップ未指定で採用断定できない。GTCRNは比較開始点|
|Star数が多ければ安全に再現できるか|人気と再現性は別。実装、重み、前処理、データ来歴、固定コミット、ライセンスを確認|
|RTFが1未満ならリアルタイムか|平均スループットの指標にすぎない。lookahead、収録/再生バッファ、tail latency、OS負荷、deadline missを別に測る|
|MVDRはなぜ破綻するか|本方式ではマスク品質・空間共分散・マイク同期等を順に検査。データなしで企業の根本原因を断定しない|
|PESQが改善したのに音が悪い場合は|同じ録音で原音・処理音をブラインド比較し、内容保持・子音・無音・少数条件を調べる。単一指標最適化を採用判断にしない|
|補聴器にすぐ載せられるか|本試作は補聴機能や臨床効果を実装・実証していない。対象製品の仕様と専門担当の検証計画が必要|
|チームをどう作るか|DSP/音声AI、embedded、音響測定、QA/NPIの責任境界を定義し、データとベンチマークを共通化。人員数は製品範囲と既存資源で見積もる|
|何を自分で実装したか|公式アルゴリズムを新規発明したとは言わず、アダプタ、監査、集計、試験、選定・検証設計という実際の範囲を説明|

## POC→量産の判定表案

|段階|確認する証拠|進めるための条件|
|---|---|---|
|POC|独立テスト、入力/前処理/重みhash、候補比較|事前に合意した品質・失敗率基準を満たす。test調整での改善は除外|
|Prototype|実時間I/O、状態管理、異常入力、ログ|因果性、時間予算、メモリ予算、fallbackの動作|
|EVT|対象基板・マイク配置での音響/電力/遅延|重要シナリオと製品性能を実機で確認|
|DVT|筐体、温度、電池条件、個体差、長時間負荷|設計検証と該当する認証試験の計画/結果を担当部門で承認|
|PVT|製造ラインでの試験・校正・歩留まり|golden unit相関、測定再現性、トレーサビリティ、版の固定|
|量産|署名済み成果物、変更管理、戻し手順|出荷版の再現ビルドと回帰試験、監視・不具合切り分け手順|

この表は求人要件を成果物へ落とした管理提案です。会議論文が当社の工程や規格への適合を証明するものではありません。製品仕様がないため、架空のms・mW・合格率を量産規格として設定していません。
